# 배분 규칙 보강

## 언제 쓰는지

`web/engine.js`의 1순위 후보가 시험 문항 또는 접수대장의 배분과와 다를 때 사용한다. 근거는 `CONTEXT.md`, `처리지침.md` 제3장, `data/배분기준표_소관키워드_304건.csv`, `data/A부_조직도_26개과.csv`, 시험 40건과 접수대장 520건이다.

## 순서

1. 원본 기준표로 시험 40건과 접수대장 520건을 채점하고, 틀린 문항을 키워드 중첩·제외어·누락 등 실제 원인별로 묶는다. 오답이 없으면 보강을 건너뛴다.
2. 원인마다 제외어 추가·키워드 추가·우선순위 조정 중 근거 있는 방법을 하나씩 제안한다. 새 규칙의 과가 조직도 26개 과에 있는지 확인하고, 원본을 바꾸지 않은 상태에서 예상 개선과 새 오답을 시험한다.
3. 사용자가 고른 방법만 `data/rules_보강.csv`에 반영한다. 원본 기준표는 보존하고, 사본이 이미 있으면 기존 변경을 확인한 뒤 적용한다.
4. 원본과 사본을 각각 읽어 시험 40건·접수대장 520건의 1순위 정답 수를 전후 표로 비교한다. 새로 틀린 문항 수와 번호도 보고한다. `web/engine.js`의 `load({rulesFile})`로 비교할 CSV를 지정할 수 있다.
5. 실제로 바꾼 규칙, 전후 결과, 남은 일과 막힌 점을 `PROGRESS.md`에 기록한다.

## 끝나는 조건

시험 40건의 1순위 정답이 30건 이상이고, 원본에서 맞았던 문항이 사본에서 새로 틀린 경우가 0건이면 통과다. 새 오답은 시험 40건과 접수대장 520건에서 모두 확인한다. 기준에 못 미치면 통과로 보고하지 않고 원인을 다시 분석해 사용자 선택을 받는다.

## 하지 말 것

- 사용자가 선택하지 않은 수정안을 적용하거나 원본 기준표·조직도·시험·접수대장을 고치지 않는다.
- 조직도에 없는 과를 추가하거나 배분 규칙을 코드에 직접 쓰지 않는다.
- 동순위·무일치 후보를 임의로 확정하지 않는다. 처리지침 제3장에 따라 `확인필요`로 남긴다.
