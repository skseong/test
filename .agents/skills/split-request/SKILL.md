# 자료요구서 문항목록 생성

이 스킬은 이 프로젝트의 `원문/` 자료요구서를 문항 단위로 분해하는 작업에 쓴다. 결과는 루트의 `split.py` 하나와 `data/문항목록.csv`다. 문항 내용이나 특정 PDF의 답을 코드에 직접 쓰지 않는다.

## 근거와 입력

- 작업 전 `PROGRESS.md`, `CONTEXT.md`의 근거 자료, `처리지침.md` 제2장을 읽는다. 기존 `split.py`가 있으면 참고해 수정하고, 없으면 루트에 새로 만든다. `99_완성본_잠금/`은 열지 않는다.
- 사용자가 교체하거나 제공한 `data/문항목록.csv`가 있으면 열 이름, 순서, 셀 표현을 목표 형식으로 삼고 기존 파일을 보존한 상태에서 비교한다. 이 프로젝트의 현재 형식은 UTF-8-SIG, 아래 8개 열이다.
- PDF 추출에는 `pypdf`만 쓴다. 없으면 `pip install pypdf`를 보여 주고 설치 허락을 받은 뒤 진행한다. 나머지는 Python 표준 라이브러리를 쓴다.

## `split.py`가 지킬 규칙

1. 첫 줄의 `○○위원회 ○○ 의원실 자료요구서`에서 위원회와 의원을 읽고, `수신: … 제출기한: YYYY. M. D.(요일) …` 줄에서 날짜를 `YYYY-MM-DD`로 바꾼다.
2. `수신:`, `담당 보좌관:`, `끝.` 줄은 문항에 넣지 않고 그 안의 이름·연락처를 출력하거나 저장하지 않는다.
3. 줄 맨 앞의 `숫자.`는 새 문항이다. `가.`, `나.`는 해당 문항의 세부항목, `※`는 비고다. 다른 줄은 직전 요구내용·세부항목·비고에 잇는다. 페이지 경계에서도 직전 문항 상태를 유지한다.
4. 열은 `파일명, 위원회, 의원, 제출기한, 문항번호, 요구내용, 세부항목, 비고` 순서다. 세부항목 여러 개는 ` / `로 잇고, 비고의 앞쪽 `※`와 뒤따르는 공백을 제거한다. 여러 비고도 ` / `로 잇는다.
5. 원문 PDF와 `data/`의 다른 파일을 변경하지 않는다. `split.py`는 PDF를 읽어 CSV를 재생성할 수 있어야 한다.

## 확인

- 파일별로 `파일명 | 파일명의 문항 수 | 뽑은 문항 수 | 마지막 번호 | 번호 연속 | 일치(O/X)` 표를 보여 준다. 번호는 1부터 마지막까지 중복·누락 없이 이어져야 한다. `일치`가 X면 원인을 원문에서 찾아 `split.py`를 고친 뒤 다시 실행한다.
- 세부항목과 비고가 모두 있는 문항 3개를 골라 원문 PDF의 해당 문항과 CSV의 요구내용·세부항목·비고를 나란히 보여 준다. 페이지를 넘긴 항목도 확인한다.
- 교체된 문항목록을 재현하는 요청에서는 `split.py`의 생성 결과를 먼저 메모리에서 기존 CSV와 **행·열·인코딩까지 비교**한다. 차이가 남으면 기존 CSV를 덮어쓰지 않는다. 일치한 뒤 `python3 split.py`를 실행한다.
- 작업이 끝나면 `PROGRESS.md`에 완료·남은 일·막힌 점을 기록한다.
